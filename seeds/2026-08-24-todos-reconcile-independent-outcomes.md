# A temporary checklist can protect independent user outcomes

- **Origin:** Pierre's 2026-08-24 durable-promise experiment direction. A
  mixed turn can require an immediate grounded answer and a later conditional
  response. Earlier commitment-specific guidance improved private persistence
  but interfered with an unrelated local-date route.
- **Intervention:** add concise guidance to the existing todo-list layer to
  make a temporary checklist when a turn has several independently valuable
  outcomes and beginning tool or asynchronous work on one could cause another
  to be dropped. Reconcile every item before replying.
- **Prediction:** the ordinary web agent will both obtain the grounded answer
  and save the future conditional response to private thread state, without a
  task-specific system-prompt rider or a delegate used merely as a checklist.
- **Boundary:** one direct outcome, a few obvious sequential actions, and
  ordinary task-list edits should not gain planning overhead. A completed todo
  is not evidence of a durable commitment: the commitment must still be saved
  in the appropriate memory store or reported as incomplete.
- **Possible experiment:** retain the frozen mixed-outcome eval panel and its
  local grounding controls. Compare the existing todo guidance against one
  general independent-outcome formulation, then run adjacent todo, grounding,
  and direct-response regressions before considering delegation.
