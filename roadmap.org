#+title: Agentic-guidance experiment roadmap

* MVP: sealed synthetic episode harness

** Status

Implemented and under local review. This is a harness milestone, not a model
study or product result.

** Outcome

Prove the experiment laboratory end to end without a model request.  A
machine-readable study definition must produce fresh, hermetic agent episodes
against an in-memory workspace, capture every provider request and tool
exchange, score a deterministic artifact, and account for every scheduled
episode in sealed records.

This milestone validates the measurement apparatus.  It produces no claim
about prompting and must not be used to change Assist. The first real profile
will be the current Assist baseline: Qwen3.6-27B Q4_K_M through Deep Agents'
LangChain tool loop, with its present reasoning setting pinned in the generic
settings object. It is not a plan-and-execute controller.

** Comparison identity

Every run has three independently sealed axes:

- Test: the fixture/task digest, natural user request, oracle, tools, and
  condition manifests. Reuse its exact digest to compare the same test.
- Model: immutable model identity and revision.
- Harness architecture: the graph/loop identity and revision, such as the
  current Deep Agents tool loop or a future plan-and-execute design.

One generic JSON =settings= field stores all behavior-affecting details of
those axes: reasoning controls, decoding, provider payload, middleware and
graph settings, limits, and future setting types. The model and architecture
identities each hash their corresponding =settings= subtree. A comparison that
changes either model or architecture creates a new sealed bundle while keeping
the test digest untouched; it never silently mixes cohorts.

** Delivered scope

- Machine-readable task, condition, and scripted-provider manifests,
  checked against a committed content-addressed StudyBundle. The bundle fixes
  the script digest, harness implementation digest, and loop limit as well as
  fixtures, schemas, and schedule.
- Sealed model and harness-architecture identities plus a generic settings
  object in each bundle and static report, so reports can be joined across the
  same test without losing provenance.
- A small agent loop over virtual list, read, write, and load-skill tools.
  The loop has no shell, network, host-filesystem, or Assist dependency.
- Exact rendered provider requests, replies, tool calls, tool results,
  and final response in a per-episode trace.
- One inspect-before-edit fixture, a deterministic artifact-and-trace
  oracle, and a scripted fake provider.
- A complete interleaved schedule from fresh fixture and provider
  state for every episode, including a simulated denied-then-admitted
  administrative attempt.  Seal admission, outcome, and static aggregate
  report artifacts.
- Integrity tests so undeclared request/schema/fixture/decoding changes,
  missing scheduled episodes, leaked review labels, and edited records fail
  closed.

Raw traces and generated result records remain local artifacts. Tests use
temporary directories and commit the fixture, condition, script, bundle, and
harness definitions.

** Acceptance checks

1. A committed bundle and script produce verified admission, outcome, trace,
   and aggregate-report artifacts, with every scheduled episode scored.
2. The fixture passes only after the expected edit and a preceding inspection;
   a write without a read fails deterministically.
3. Each episode starts with a new virtual workspace, tool state, provider, and
   message history.
4. The runner rejects a manifest whose digest, rendered request, schema,
   fixture, or decoding diverges outside its declared condition difference.
5. The existing and new integrity tests pass without a model, GPU, network, or
   production Assist state.

** Explicitly deferred

- A real-model provider client and the coordinator that invokes one bounded
  trial through =tools/agentic resource run llm=. Its first profile must use
  the current Assist model and Deep Agents architecture described above.
- Git-tag binding for a real-model bundle, seed-support calibration, and any
  model trial.
- Registered Study A task-bank authoring, pilot, confirmation analysis, and
  qualitative review.

Those require the MVP checks and the required written scientific-integrity,
statistical-rigor, and agentic-harness-fit reviews before any model result.

* Next milestones

** Current Assist baseline admission coordinator

Add a coordinator that can advance only the sealed schedule prefix, records a
denied admission against the current episode, and starts exactly one bounded
episode through the workspace LLM resource. It has no direct-model mode. Bind
the first registration to the observed Qwen3.6-27B Q4_K_M model and the current
Deep Agents 0.6.1 / LangChain 1.3.1 / LangGraph 1.2 tool-loop architecture,
including reasoning disabled. Require a model-weights digest before it admits
any real trial.

** Study A development registration

Register the frozen development task bank for the 2x2 system-guidance by
loaded-skill-guidance study.  Pin model and decoding configuration, lock the
primary artifact oracle, then run only after the coordinator and study reviews
are complete.

** Study A confirmation

Create a new confirmation registration with a separate task cohort, fixed
sample plan, and analysis revision.  Report every scheduled episode and retain
the limits of inference to the pinned model, loop, and tasks.
