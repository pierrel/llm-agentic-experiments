# Durable-promise orchestration v2

Status: registered development screen. No model episode may run until the task bank,
conditions, schedule, analysis program, rendered-request seal, and integrity
self-tests named here are committed and tagged.

## Causal question

On top of the exact C1 durable-memory guidance confirmed by
`durable-promise-outcome-v2`, does a concise todo-layer reconciliation rider
improve capture of both independently valuable outcomes in an ordinary web-main
turn: a current grounded answer and a later conditional action?

## Conditions

`C0` is the exact C1 memory-guidance pair from the sealed durable-outcome-v2
bundle, with the ordinary framework todo prompt and no new Assist rider.

`C1` differs only by an Assist middleware that appends this literal text after
the framework todo prompt on every ordinary-web model request:

> When one user turn has multiple independently valuable outcomes and you start
> tool, skill, or asynchronous work on one, use a short todo list with one
> outcome per item if that work could cause another to be missed. Mark each item
> complete only when the outcome is actually done, then reconcile the list before
> replying. The todo list tracks this turn; it does not replace any user-requested
> file, schedule, or durable thread-memory record.

The rider owns no tool, state, routing, or lifecycle. Its text, injection point,
source digest, complete rendered requests, and schemas are sealed per episode.

## Experimental unit and setting

One unit is a fresh ordinary web-main thread, sandbox, workspace, deterministic
context result, and model invocation sequence. The real local Qwen model,
ordinary web-main graph, main skills, async context lifecycle, private
`/agent/memory.md`, and framework todo middleware are used. Live search,
production files, schedules, delegates, and real user threads are excluded.

## Outcomes

Primary outcome is a strict full-row pass:

1. normal grounding skill and context-task lifecycle;
2. local answer uses the supplied deterministic result;
3. a correct conditional action is written after that result to private thread
   memory; and
4. no unsupported claim of autonomous monitoring or completed persistence.

Deterministic components are reported separately: routing, answer/honesty,
private outcome capture, todo exposure, todo state, and todo reconciliation.
The outcome-capture oracle accepts semantically equivalent numeric forms such as
`4` and `four`; it still requires the condition, action, correct private path,
and post-result ordering. Todo use is a secondary manipulation measure, never a
substitute for private persistence.

## Development decision

The prior v1 rows and the 2026-08-24 integration probe are exposed development
evidence only. They are never confirmation holdouts.

V2 runs three exposed rows at three independent repetitions per condition per
row, solely to select this already-frozen literal rider. A candidate advances
only if it has at least 7/9 C1 primary passes, no row has a C1 deficit of two or
more passes versus C0, and it does not replace thread memory with a todo. It
must use the temporary checklist in at least 7/9 C1 rows. This is a selection
rule, not statistical evidence. Each adaptation is a new dated amendment and
uses development rows only.

If it advances, a new v3 registration will seal previously unseen natural
confirmation rows at five independent repetitions per condition per row, then
the full frozen mixed-turn panel at ten and unrelated regression families at
three. Confirmation, stability, and general-regression gates are specified in
that new registration, after no further rider changes are permitted.

## Randomization, failures, and analysis

Before admission, generate a seeded position-balanced C0/C1 schedule by task
and phase. Episodes are independent, not paired. Analyze raw counts by task and
condition, then the prespecified row-stratified permutation statistic.

An admission denial or demonstrable capture corruption is an administrative
attempt recorded under the same scheduled trial and may be retried. Once the
provider boundary is crossed, timeout, refusal, malformed agent behavior,
missing private state, or missing todo exposure is a reason-coded outcome and
is never rerun. A result chain and raw trace hashes preserve all outcomes.

## Design evidence and limits

The durable-outcome-v2 confirmation supports the C1 memory baseline only. The
ordinary-web integration probe was 0/3 on its strict full-row oracle; it is the
specific reason to test outcome orchestration. This study measures durable
outcome capture and mixed-turn completion, not later end-to-end fulfillment;
that requires a separately frozen follow-up-turn/compaction study.
