# Durable-promise capability routing v4

Status: registered pilot. No model episode has run in this version.

V4 is a clean successor to the preserved exploratory work and the v1-v3
pre-request infrastructure events. None produced a provider request, tool call,
agent response, or baseline observation. Their sealed private evidence remains
at their versioned event records and is never replayed.

The scientific question, four natural pilot rows, counterbalanced 24-episode
C0/C1 schedule, R/P/A/F observables, and count-only advance rule are unchanged
from v3. `C0` is the exact current grounding description. `C1` adds only this
general boundary: “A question about the user's own date, time, meeting,
deadline, or status needs this skill when the answer comes from their records.”
No model-visible prompt, skill, schema, tool, fixture, model, or scoring change
is introduced by the successor.

The only harness change retains the tail of a failed worker traceback instead
of its generic beginning. This is private error evidence, not an outcome
intervention. Its purpose is to identify a pre-provider process failure without
mistaking it for model behavior. Any pre-request failure remains terminal and
is preserved, never silently replayed.

V4 advances only if C1 has at least two more R and F successes than C0 across
the 12 rows per condition, with no P or A decrease for either lower-conflict
sentinel. The pilot selects no release candidate. A separate unseen confirmation
bank and the fixed product regression panel remain mandatory before release.
