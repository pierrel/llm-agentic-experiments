# Durable-promise outcome completion v2

Status: registered design. No model episode has run in this cohort.

## Question and fixed candidate

Does the v1 memory-scope treatment, kept byte-for-byte identical, improve
durable conditional future actions after grounded local work on unseen natural
requests, without a material routing or honesty regression?

C0 is the current Assist repository-memory and thread-memory prompt pair. C1
is the exact v1 treatment pair. To avoid duplicating long immutable prompt
prose, `conditions.json` references each v1 condition by a SHA-256-pinned
source file; the v2 bundle hashes the fully resolved prompt pairs. This is not
a new treatment or a new source of discretion.

## Fresh confirmation setup

The four fresh rows are orchard volunteer, passport form, choir rehearsal, and
vet follow-up. Each combines one fact available only from a deterministic
local context result with one independent later condition-action. They share no
user wording, fixture content, local facts, or commitment terms with v1 or the
earlier routing studies.

Each row has six fresh C0/C1 replicate blocks, for 48 episodes total. Six is a
whole number of two-condition position cycles: each condition is first three
times and second three times for each task. The fixed schedule is generated
before admission with independent recorded generation seeds. The local model
does not advertise seed support, so a block controls order rather than claiming
paired sampling.

## Outcomes and decision rule

R requires grounding first, context next, and a checked local result before
dependent work. P requires the requested post-result `/agent/memory.md` write.
A requires the local fact in the response and no unsupported completion claim.
F requires R, P, and A. All are deterministic predicates over the captured
tool/message/file evidence.

P and F are co-primary outcomes. C1 advances to a product-candidate regression
panel only if, across all 24 episodes per condition:

1. C1 has at least six more P successes and six more F successes than C0
   (a 25-point absolute improvement);
2. each co-primary contrast has a one-sided exact paired sign test of the
   discordant replicate blocks at `p <= 0.05`; and
3. C1 is not lower than C0 by more than two R successes or two A successes,
   overall or on any one task.

The co-primary rule requires both endpoints, so no multiplicity adjustment is
used for those two necessary conditions. R and A are protection gates, not
additional positive claims. Per-task rows and two-sided Wilson intervals are
descriptive only: four fixtures do not establish a population-level task effect.

Every scheduled episode remains in the denominator. A timeout, refusal, invalid
tool call, provider error, or post-request recovery error is a failed P/F/R/A
outcome with its reason retained. An infrastructure-invalid event is retried
only when its lifecycle record proves no model request began. Admission denial
is administrative, preserves the same trial, and never changes order.

## Integrity contract

The runner closure includes the coordinator and shared `harness/` accounting
modules. It binds the Assist source and EDD fixture closure, model id, context
length, non-secret provider-endpoint digest, temperature, and reasoning setting
before the first provider request. The local server does not expose a reliable
weights digest, so this cohort does not claim one; the bounded served identity
is model id plus endpoint digest and context length. Every lifecycle marker has
a Linux process-identity fingerprint, preventing PID reuse from masquerading
as a running worker.

The sole supported runner nests each worker in `tools/agentic resource run llm`.
Same-user code cannot prove that wrapper cryptographically, so this remains a
documented operator and review invariant, not a security claim. Raw traces stay
in a 0700 local directory; their hashes, sealed chains, bundle, and result
report are preserved in the result capsule.

V1's recorded R/F-versus-prose-P/F discrepancy is why this new cohort has an
explicit executable P/F rule in the bundle registration. V1 selected the fixed
candidate but supplies no rows to this confirmation analysis.

## Interpretation

A pass would support shipping this narrow prompt-only candidate to the existing
Assist regression panel. It would not prove that the treatment works for all
memory, reminder, scheduling, or research requests. A mixed or failing result
rejects this candidate as currently written; it does not authorize tuning on
these observed rows.
