# Reach-for-instructions development registration v3

V2 was sealed but never admitted to a model. Its runner created a new raw-output
directory without passing mode `0700`, then correctly rejected the resulting
mode `0755` before it started the worker. V3 changes only new-output creation to
request `0700`. V1 and V2 remain immutable unexecuted setup records.

The question, two delivery modes, fixture, user request, three inert context
doses, 18-episode interleaved schedule, model, reasoning setting, architecture,
decoding, tool set, JSON-plus-procedure oracle, and interpretation rule are
unchanged from V2. The local provider has no sealed generation-seed control;
trial seeds identify scheduled episodes only. Every admitted terminal episode
remains reason-coded, and any admission denial retries that exact sealed trial.

This is an exploratory development screen, not a confirmation result or a
claim of transfer beyond the pinned model and current Assist Deep Agents loop.
