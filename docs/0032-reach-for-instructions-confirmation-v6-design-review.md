# Reach-for-instructions confirmation V6 design review

## Proposed minimum adequate setup

V5 is retained as a valid sealed execution record, but its all-zero primary
result does not identify a guidance effect: the semantic oracle rejected every
otherwise grounded unresolved-attachment handoff, and both arms loaded the same
named guide. V6 therefore uses one fresh equipment-return task, one fixed
Deep Agents filesystem/tool loop, one named loader schema, three predeclared
context doses, 12 fresh trials per cell, and no extra agents, tools, judges, or
external dependencies.

Current Assist Qwen3.8 construction is explicit: reasoning enabled, temperature
0.1, no client output cap, and the live 131,072-token context window. The
runner verifies the actual post-middleware provider request before scoring.

## Scientific-integrity review

- **Finding, fixed:** V5 task results cannot inform an amendment. V6 uses a
  distinct fixture, fresh randomization, new study ID, and an immutable tag.
- **Finding, fixed:** V5's observed unresolved `attached` wording is now a
  pre-admission calibration case paired with a direct false assertion. The
  oracle cannot be broadened after V6 requests begin.
- **Finding, fixed:** G01 no longer advertises the guide name. The schema stays
  fixed, but G01's complete procedure and G02's discoverable guide are the
  explicit delivery packages.

## Statistical-rigor review

- **Finding, accepted:** 12 trials per cell is retained from the confirmation
  plan. It supports a stable descriptive cell comparison, not a precise
  interaction estimate or a general product claim.
- **Finding, fixed:** all terminal outcomes remain in the hash chain; admission
  refusals retry the same schedule entry and are reported separately.
- **Finding, fixed:** load timing is measured before primary scoring, so a
  primary failure cannot erase the declared process outcome.

## Agentic-harness-fit review

- **Finding, fixed:** V5's pinned profile had reasoning off and a 1,200-token
  cap. V6 explicitly constructs Qwen3.8 with reasoning on and leaves
  `max_tokens` unset, matching current Assist main.
- **Finding, fixed:** pre-render and live workers use the same construction and
  fail closed if model identity, reasoning body, output-token policy, fixture,
  tool schema, or first provider request differs from the sealed bundle.
- **Risk, retained:** the minimal harness is a direct Deep Agents loop, not all
  Assist product middleware. This study estimates the named harness setting
  only; it does not claim a full production-thread effect.

## Minimum-setup review

The separate fixture, calibration corpus, current profile, loader schema,
context strata, deterministic oracle, and fixed sample are necessary to answer
the registered contrast. Full Assist prompts, subagents, browsing, real user
files, an LLM judge, additional skill catalogs, and product changes are not.
