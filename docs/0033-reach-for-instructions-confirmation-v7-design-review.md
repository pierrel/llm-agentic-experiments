# Reach-for-instructions confirmation V7 design review

## Minimum adequate setup

V6 is retained as a partial, non-diagnostic execution because its preregistered
oracle rejected a compact but source-supported status form. The narrow repair
is not to amend V6, but to use a fresh task and a pre-admission calibration that
models the observed representation boundary. V7 therefore retains one private
Deep Agents filesystem/tool loop, one loader schema, three context doses, 12
trials per cell, and the current Assist Qwen3.8 profile. It adds no extra
agent, judge, tool, or product prompt.

## Review findings

- **Scientific integrity, fixed:** V7 uses a new Harborline Systems fixture and
  new randomization. V6 outcomes remain separate and cannot influence this
  schedule.
- **Oracle, fixed:** the corpus accepts `not_completed` only when a separate
  approval field says that approval is conditional on the photo. It rejects the
  same compact status without that fact, invented completion, and an unsupported
  label assertion.
- **Contrast, retained:** G01 gets the complete procedure and no discoverable
  guide name. G02 gets only the named guide catalog entry and must load it to
  receive the procedure. The loader schema itself remains fixed.
- **Harness fidelity, retained:** request capture and workers use current
  Assist construction with reasoning on and `max_tokens` omitted. The captured
  post-middleware request is hashed before sealing and verified by each worker.
- **Scope, retained:** this estimates this Qwen3.8/Deep Agents/task setting. It
  does not establish a general skill design rule, a context threshold, or a
  production Assist effect.

## Decision

The fixture, condition-blind oracle corpus, process measure, fixed profile,
context strata, and 72-episode schedule are required for the question. A full
Assist thread, multiple skill catalogs, real user files, extra treatments, or
an LLM judge would expand scope without resolving V6's actual boundary.
