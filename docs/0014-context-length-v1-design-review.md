# Context-length development v1 design review

Date: 2026-08-25. This review is completed before any trial in the registration.

## Scientific integrity

The filler is generated from a fixed inert template, appears only before the
unchanged procedure, and has no case terms, paths, instructions, or answer
cues. The fixture, model, decoding, agent loop, and oracle are identical across
conditions. Each fresh trial runs through shared GPU admission and retains its
raw trace locally under a hash in the result capsule.

## Statistical rigor

This is a three-episode development screen, not a powered estimate. The unit
is one fresh episode. The sole primary outcome is the deterministic conjunction
of procedure and artifact. Provider-reported first-request tokens record the
actual dose. A single three-condition block cannot balance position, so the
bundle declares position adjustment and interpretation is explicitly limited.

## Agentic harness fit

The worker calls Assist's reasoning-disabled model selector and Deep Agents'
normal virtual filesystem loop. It supplies no caller-provided external tools,
production filesystem, user data, network capability, or subagents. The default
Deep Agents filesystem, TODO, and general-purpose task capability profile
remains available. The trace records the actual Deep Agents messages and checks
observed inventory, reads, and write ordering. This is a controlled
current-architecture approximation, not a web thread or full Assist session.
Before invocation, the worker compares the selected endpoint model, reasoning
switch, Assist commit, and Deep Agents/LangChain/LangGraph versions with the
sealed runtime contract.

## Minimum adequate setup

Three sizes are the least sweep that can distinguish an immediately failing
context from a gradual or late change. One synthetic task, one replicate,
filesystem tools, no skills, no qualitative judge, and no alternate model or
architecture are held to the minimum needed to screen this causal factor.

## Resolutions

- The default Deep Agents tool schemas are recorded as a sealed capability
  profile, while actual calls and full messages are retained in raw traces.
- The model GGUF is explicitly hashed because model ID alone is insufficient.
- A no-difference result triggers new registrations, never a changed completed
  bundle or replay of completed episodes.
